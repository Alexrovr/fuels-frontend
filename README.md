## Лабораторная работа №5

SPA на React для **гостя**. Услуга курса — вид топлива (метан, пропан-бутан, ацетилен, водород…).

Две страницы — **лента** и **плитка**, аналогичные SSR-страницам из ЛР1. Данные берутся из веб-сервиса ЛР3–ЛР4 (`/api/fuels…`) — репозиторий
[fuels-backend](https://github.com/Alexrovr/fuels-backend);
если он не запущен, карточки показываются из коллекции mock-объектов.

## 1. Стек

| | |
|---|---|
| Язык | TypeScript |
| Библиотека интерфейса | React 19 (только функциональные компоненты и хуки) |
| Сборщик и dev-сервер | Vite 8 (`@vitejs/plugin-react`) |
| Роутинг | `react-router-dom` 7 (`BrowserRouter`, вложенные `Route`, `Outlet`) |
| Компоненты | `react-bootstrap` + `bootstrap` 5 (`Card`, `Button`, `Form`, `Form.Range`, `Nav`, `Row`/`Col`, `Spinner`, `Badge`) |
| Управление состоянием | только локальный `useState` страниц; **без Redux и без React Context** |

## 2. Запуск

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # проверка типов (tsc -b) и сборка в dist/
npm run lint       # oxlint
```

Для работы с реальными данными рядом поднять бэкенд (папка `fuels-backend`):
`docker compose up -d` (Postgres, Minio, Redis) и `go run ./cmd/app` (порт 3030).
Без бэкенда приложение тоже работает — на mock-данных.

### Подключение к веб-сервису

Dev-сервер Vite проксирует запросы на бэкенд (`vite.config.ts`):

| Путь во фронтенде | Куда уходит |
|---|---|
| `/api/*` | `http://localhost:3030/api/*` — JSON API |
| `/resources/*` | `http://localhost:3030/resources/*` — медиа по умолчанию, которые бэкенд отдаёт относительными путями |

Для браузера и страница, и API находятся на одном origin `localhost:3000`, поэтому CORS на бэкенде не нужен.

### Когда используются mock-данные

`src/modules/fuelsApi.ts` сначала делает запрос к веб-сервису (таймаут 3 с).
Если сети нет, запрос не уложился в таймаут или пришёл ответ 5xx (бэкенд выключен —
прокси Vite отвечает `502 Bad Gateway`), данные берутся из `src/modules/mock.ts`, а на странице
появляется пометка **mock — веб-сервис недоступен**. Фильтр и «Следующий» на mock работают
так же, как на бэкенде: `heat_of_combustion_kj >= min_heat`, следующая карточка — по кругу,
черновики гостю не показываются. Ответ 404 — настоящий ответ веб-сервиса, mock вместо него не подставляется.

Mock работает **без БД и без S3**: фото и видео mock-карточек — копии объектов из бакета Minio,
они лежат в самом проекте, в `public/mock/`, и отдаются dev-сервером (`/mock/metan.jpg`, `/mock/methane.mp4`…).

## 3. Страницы

Макет — вертикальный экран телефона: на компьютере приложение показывается колонкой 420 px по центру.
Сверху у всех страниц панель с логотипом **HEATCALC** и названием страницы,
снизу — навигационная панель.

### 3.1. Нижняя навигационная панель

`components/TabBar` — `Nav` из React-Bootstrap, 4 пункта:

| Пункт | Адрес | Доступность |
|---|---|---|
| ▶ Лента | `/feed` | доступен; активен на `/feed` и `/feed/:id` |
| + Добавление | — | **недоступен** гостю (`disabled`, серый) |
| ▦ Плитка | `/grid` | доступен; активен на `/grid` |
| ➜ Вход | — | **недоступен** гостю (`disabled`, серый) |

Активный пункт подсвечивается акцентным цветом и полосой сверху (класс `active` ставит `NavLink`).

Корень `/` и неизвестные адреса перенаправляются на плитку (как `/` в SSR-версии).

### 3.2. Плитка — `/grid`, `/grid?min_heat=50000`

Запрос: `GET /api/fuels?min_heat=<число>` (без фильтра — `GET /api/fuels`).

| Элемент | Описание |
|---|---|
| Слайдер **«Теплота сгорания не менее, кДж/м³»** (`Form.Range`) | 0 – 110 000 с шагом 1 000, подписи делений 0 / 27 500 / 55 000 / 82 500 / 110 000 |
| Надпись «от N кДж/м³» | текущее положение слайдера |
| Кнопка **Найти** | применяет фильтр: значение записывается в адрес (`?min_heat=`), карточки загружаются заново; пока идёт загрузка, кнопка недоступна |
| Пометка **mock** | видна, если данные взяты из mock |
| Карточки в два столбца (`Card`) | изображение, название, теплота сгорания, число лайков. Нажатие на карточку — переход в ленту на эту карточку (`/feed/:id`) |
| «Нет видов топлива…» | если под фильтр ничего не подошло |

Фильтр хранится в адресе, поэтому сохраняется при перезагрузке страницы и кнопке «Назад» браузера.

### 3.3. Лента — `/feed`, `/feed/:id`

Запросы: `GET /api/fuels/feed` (первая карточка), `GET /api/fuels/feed/:id`,
`GET /api/fuels/feed/:id?next=true` (следующая).

| Элемент | Описание |
|---|---|
| Видео на весь экран | `video_url` карточки; постер — `image_url` |
| Название и описание реакции | слева снизу; описание свёрнуто до двух строк |
| Кнопка **Больше / Меньше** | разворачивает и сворачивает описание |
| Колонка справа: **Теплота сгорания**, кДж/м³ и **Воспламенение**, °C | два поля услуги по теме |
| ❤ и число | количество лайков (поставить лайк гость не может) |
| Кнопка **Следующий** | загружает следующую опубликованную карточку (по кругу) и меняет адрес на `/feed/<её id>` |
| «Такого вида топлива нет в справочнике» + кнопка **Вернуться к плитке** | если карточки с таким id нет |

## 4. Изображение и видео по умолчанию

Файлы лежат в самом проекте, в `public/`, и отдаются dev-сервером:
`/DefaultImage.svg` и `/DefaultVideo.mp4` (`src/modules/media.ts`).

- поле `image_url` / `video_url` **пустое** → сразу подставляется файл по умолчанию
  (`imageOrDefault`, `videoOrDefault`); в mock так сделаны «Этилен» и «Угарный газ»;
- поле **заполнено, но файл не загрузился** (Minio выключен, объект удалён) → обработчик
  `onError` у `<img>` / `<video>` меняет `src` на файл по умолчанию.

## 5. Структура

```
fuels-frontend/
  index.html                 точка входа, <div id="root">
  vite.config.ts             порт 3000, прокси /api и /resources на бэкенд :3030
  public/                    DefaultImage.svg, DefaultVideo.mp4, favicon.svg
    mock/                    фото и видео mock-карточек (метан, пропан-бутан, ацетилен, водород)
  src/
    main.tsx                 createRoot, StrictMode, подключение bootstrap.css
    App.tsx                  маршруты /feed, /feed/:id, /grid внутри AppLayout; остальное → /grid
    AppLayout.tsx            оболочка «телефона»: TopBar + <Outlet/> + TabBar
    Routes.ts                адреса и подписи страниц
    modules/
      fuelsApi.ts            типы FuelListItem/FuelDetail, getFuels, getFeedFuel, переход на mock
      mock.ts                FUELS_MOCK — 7 видов топлива (6 опубликованных, 1 черновик)
      media.ts               медиа по умолчанию
    components/
      TopBar/                логотип и название страницы
      TabBar/                нижняя навигация из 4 пунктов
      HeatFilter/            фильтр-слайдер плитки
      FuelCard/              карточка плитки
      SourceNote/            пометка «mock»
    pages/
      GridPage.tsx           плитка
      FeedPage.tsx           лента
```

## 6. Компоненты и props

| Компонент | Props | Состояние |
|---|---|---|
| `HeatFilter` | `value: number`, `setValue(value)`, `onSubmit()`, `loading?`, `max?` (110 000), `step?` (1 000) | нет — контролируемый компонент, значение хранит `GridPage` |
| `FuelCard` | `fuel: FuelListItem`, `onClick()` | нет |
| `SourceNote` | `overlay?: boolean` — вариант поверх видео | нет |
| `TopBar`, `TabBar` | — (адрес берут из роутера) | нет |

## 7. Хуки

| Хук | Где | Зачем |
|---|---|---|
| `useState` | `GridPage` | положение слайдера `minHeat`, карточки `fuels`, `fromMock`, `loadedMinHeat` (из него вычисляется `loading`) |
| `useState` | `FeedPage` | карточка `fuel`, `fromMock`, `loading`, `noteOpen` (Больше/Меньше) |
| `useEffect` | `GridPage` | загрузка карточек при открытии и при смене `min_heat` в адресе; cleanup ставит `ignore = true`, чтобы устаревший ответ не перезаписал состояние |
| `useEffect` | `FeedPage` | загрузка карточки при открытии и смене `:id`; пропускает запрос, если карточку уже загрузила кнопка «Следующий» |
| `useSearchParams` | `GridPage` | чтение и запись `?min_heat=` |
| `useParams` | `FeedPage` | `:id` карточки из адреса |
| `useNavigate` | `GridPage`, `FeedPage` | переходы по кнопкам и карточкам |
| `useLocation` | `TopBar` | название текущей страницы по адресу |

В режиме разработки `StrictMode` монтирует компоненты дважды, поэтому во вкладке Network запрос
при открытии страницы виден два раза; в production-сборке (`npm run build`) — один.
